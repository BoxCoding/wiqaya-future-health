01 The problem

Calendar rules invite people on a schedule. Risk doesn't follow a schedule.

Eligibility for Well-Child Visits and adult screening still leans on age and sex. The families with the highest unmet need sit in signals a rule never reads, so they are missed, invited late, or sent to the wrong pathway.

03 What makes Wiqaya different

We don't just find who is at risk. We find who an invitation will help.

Invite for benefit

Priority = risk × invitation lift. Real clinic slots go to the households where an invite changes attendance.

The household is the unit

A child's Well-Child Visit and a parent's screening booked back to back, with each adult's consent.

Correct for the never-screened

Trained only on people who were screened, so under-served families aren't scored down for missing data.

AI that can't invent figures

Six agents; the model frames and selects, code writes every fact, a safety agent blocks drift.

Synthetic population module app/data.py feeds the engine; its hidden ground truth is used only to score outcomes and is never returned by the API.

06 High-level design · key flows

Two paths: the weekly batch and the question

Weekly batch (startup, about 5 s for 41,745 people)

  1. Build or load the population and consent flags
  2. Fit the risk model on screened adults only, plus 20 bootstrap refits
  3. Fit the lift model on past randomised outreach
  4. Run care-gap rules for every person
  5. Priority = need × lift for everyone with a gap and outreach consent
  6. Fill 150 slots per centre with whole households, best benefit per slot first
  7. Assign back-to-back slots, skipping 12:00–13:00
  8. Compose household messages; score both policies

A question to Ask Wiqaya (2–6 s on Gemini)

  1. Rate limit and length validation
  2. Supervisor routes: population, case brief or safeguards
  3. Query planner: rules first, model proposes typed JSON filters
  4. Verifier keeps only filters the question supports
  5. Analyst tool runs engine.query(); cells under 10 hidden
  6. Code writes every fact as a verified sentence
  7. Writer agent returns a fact-free lead plus which facts to show
  8. Safety agent checks the lead; one revision, then the rule-based answer

09 Low-level design · algorithms

The maths, kept small and explainable

Risk model

  • L2-regularised logistic regression by Newton steps (numpy)
  • Features: age, BMI, prediabetes, family history*, genomic finding*, visit history (*only if consented)
  • Bias correction: trained only on screened adults; a never-screened person can't test positive
  • 80% interval from 20 bootstrap refits; explanation = exact additive log-odds vs the average adult

Invitation lift

  • T-learner: one logistic model for invited, one for not invited, on past randomised outreach
  • Lift = P(attend | invited) − P(attend | not invited), clipped at 0
  • Area context used only here, never for eligibility; withheld → population average

Weekly plan

  • Priority = need × lift (adults: modelled risk; children: rules)
  • Group by household; rank by mean priority per slot; greedy fill to 150 slots, skipping households that don't fit
  • Slots: 20 min, 2 rooms, 08:00–16:00, 12:00–13:00 kept free, Monday–Friday

Safety agent

  • Lead must have no digits, number words, names, places, claims (percent, completed, target, trend…) or diagnostic words
  • Patient briefs also block clinical orders (requires, must)
  • Facts always shown in natural order; required facts are never dropped

11 Responsible AI, safety and data governance

Privacy by design, visible on every screen

Consent ledger

Six data categories per person. Withheld data is never used, and each flag shows exactly what it read.

Message privacy

Adults' screening joins the family message only if they opted in. Teens 14+ get a confidential note. Genomic results are never named.

Fairness gates

Every segment's reach must be ≥ 80% of overall reach. Below-gate groups get outreach redesign, not silence.

Small-cell suppression

Any group under 10 people is hidden, plus a complementary cell so totals can't reveal it.

Clinician decides

Population prioritisation, never diagnosis. Accept, change or decline on every gap; every decision logged.

Safe operations

Synthetic data only in the demo; local LLM path for real data; API key in a git-ignored file, sent in a header; AI rate limit.

16 Assumptions and limitations

What we'd tell a clinical review board

Assumptions

  • All data is synthetic; results are scored against a simulated ground truth
  • Screening intervals, start ages and the adolescent age (14) are placeholders for DoH-approved values
  • Past outreach was randomised, which makes invitation lift learnable

Limitations and next steps

  • No sign-in yet; clinician decisions held in memory (PostgreSQL in the pilot)
  • Arabic templates need native-speaker and clinical review
  • Children prioritised by rules only; paediatric model on the roadmap
  • Map is schematic; the rate limit is per process
